# Validation

Validated locally on 21 October 2026. These are native host tests and execution of the compiled ARM app in NumPlay's Unicorn emulator. No physical calculator measurements are claimed.

## Storage optimisation and campaign boundary

- App size decreased from 127,344 to 90,208 bytes: **29.16% less storage**. Static RAM and the rendering buffer are unchanged.
- All 295 sprite images were compared with digests from the previous app: every pixel, palette colour and anchor is unchanged. `tests/test_artwork.py` repeats this check on the compiled app.
- Native before/after physics were compared over 9,472 frames covering all 50 courses: the motion states match exactly for the same inputs. The first 39 original courses retain their layouts. The eleven added fixed courses use original sections.
- The final level stores 50/50 completion, displays the ending and offers replay instead of level 51. Every skin is obtainable by finishing the campaign.
- Old `SHK1` saves migrate to `SHK2`; progress above level 50 is clamped to a completed campaign, with valid progress and seed retained. New-format invalid/out-of-range states are rejected.

## Checks performed

- Compiled with GCC 15.2.1 for Cortex-M7, hardware single-precision floating point, `-Os -flto -Wall -Wextra -Werror`.
- Host unit tests: attach/release momentum, keeping the same hook while holding, guarded zero-length rope, restart/finish state, valid deterministic courses and corrupt save rejection without partially applying bad data.
- Endurance: 300 courses, up to 2,400 ticks each, with varying button input; all states remain finite and bounded by the data structures.
- Playability search: all 50 fixed campaign courses completed using only hold/release sequences, with no teleporting, modified physics or skipped collisions. Replays are generated by `tests/playability.c`.
- Source comparison: 9,472 independent frame transitions compared with the actual JavaScript functions extracted from the supplied game, including 31 wall-collision frames and 93 bumper-collision frames. The largest position difference was 0.000002383 world units, under 0.0006 display pixels for one transition. This measures local frame agreement, not identical long-run floating-point trajectories. The largest angular-speed difference was 0.001642 rad/s in short-rope cases.
- The comparison caught and fixed an initial collision discrepancy: the source checks endpoints before the interior of each wall segment. The native code now preserves that order and checks all bumpers before all walls.
- All 50 fixed courses executed and rendered as ARM code, including dense rotated-wall layouts. No protected RAM or firmware-call violations were detected.
- Four ARM environments passed menu/play/pause/resume, save/reload, Home/Power exit, firmware-RAM preservation and app-RAM clearing. N0115 uses the N0110 CPU model with a conservative smaller app RAM region.

| Profile | App RAM budget | Pause/save/reload/safe exit |

| N0110 / Epsilon | 148,928 | Pass |

The emulator observed a maximum 10 ms render cost and no frames exceeding the 33 ms display budget in these scenes. These are virtual CPU measurements, not LCD or physical-device benchmarks. Simulation advances at a fixed 60 Hz with four collision substeps and bounded catch-up; display updates target 30 Hz.

A full filesystem was also tested: retry saving, continue playing, retry exiting, and exit without saving all work while preserving the existing file byte-for-byte. A held OK key on launch does not accidentally start a game.

The original title, palettes, poses, level geometry, skins, victory platform and English menu layouts were inspected in rendered captures. Screenshots are in `docs/`; reproducible detailed reports are generated under ignored `output/`.

## Repeat

```sh
python build.py --arm-bin /path/to/arm/bin --nwlink /path/to/nwlink/bin/nwlink
make test-fidelity HOST_CC=cc
make test-arm NWLINK=nwlink
```

`tools/assets.py` requires Pillow. The ARM checks require the emulator dependencies documented in NumPlay. The source-physics comparison requires Node.js and a host C compiler.
